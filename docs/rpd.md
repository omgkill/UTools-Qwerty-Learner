# Qwerty Learner 产品需求文档

## 产品概述

Qwerty Learner 是一款基于 uTools 平台的单词学习工具，通过打字练习帮助用户记忆英语单词。用户在输入单词的过程中建立肌肉记忆，同时通过间隔重复算法科学安排复习周期。

**核心价值：**
- 打字练习建立单词肌肉记忆
- 间隔重复算法优化记忆效率
- 多词典支持满足不同学习需求

## 功能模块一：正常学习模式

### 1.1 功能概述

间隔重复算法驱动的日常学习流程，自动调度复习与新词学习。

### 1.2 核心规则

| 规则 | 说明 |
|-----|-----|
| 学习上限 | 每日最多学习 N 个单词（复习 + 新学合计不超过上限） |
| 学习顺序 | 到期词优先复习，复习完成后才学习新词 |
| 完成判定 | 学满每日上限数量，或无更多单词可学 |

### 1.3 学习流程

```
用户打开应用
        ↓
系统判断：今天学了几个？
        ↓
┌─────────────────────────────────────┐
│  今日已学数量 < 每日上限              │
│  → 继续学习                          │
│                                      │
│  今日已学数量 ≥ 每日上限              │
│  → 显示「今日学习完成」               │
└─────────────────────────────────────┘
        ↓ 继续学习
系统判断：有没有到期词？
        ↓
┌─────────────────────────────────────┐
│  有到期词                            │
│  → 取到期词，逐个复习                │
│                                      │
│  无到期词                            │
│  → 跳到「新词学习」                  │
└─────────────────────────────────────┘
        ↓ 复习到期词
用户逐个输入单词
        ↓ 每完成一个
系统判断：是否达到上限？
        ↓
┌─────────────────────────────────────┐
│  已达上限                            │
│  → 显示「今日学习完成」              │
│                                      │
│  未达上限                            │
│  → 继续下一个到期词                  │
└─────────────────────────────────────┘
        ↓ 到期词全部复习完，未达上限
系统判断：有没有新词？
        ↓
┌─────────────────────────────────────┐
│  有新词                              │
│  → 计算剩余配额，取对应数量新词       │
│  → 逐个学习                          │
│                                      │
│  无新词                              │
│  → 显示「今日学习完成」              │
└─────────────────────────────────────┘
        ↓ 学习新词
用户逐个输入单词
        ↓ 每完成一个
系统判断：是否达到上限？
        ↓
┌─────────────────────────────────────┐
│  已达上限                            │
│  → 显示「今日学习完成」              │
│                                      │
│  未达上限 + 还有新词                 │
│  → 继续下一个新词                    │
│                                      │
│  未达上限 + 无新词                   │
│  → 显示「今日学习完成」              │
└─────────────────────────────────────┘
```

### 1.4 场景举例

**场景 1：有到期词，未达上限**

| 条件 | 结果 |
|-----|-----|
| 到期词 5 个 | 先复习这 5 个 |
| 上限 20 个 | 复习完后，学 15 个新词 |
| 新词充足 | 总计学满 20 个，显示完成 |

**场景 2：到期词超过上限**

| 条件 | 结果 |
|-----|-----|
| 到期词 25 个 | 只复习前 20 个 |
| 上限 20 个 | 学满 20 个，显示完成 |
| 剩余 5 个 | 明天继续复习 |

**场景 3：无到期词**

| 条件 | 结果 |
|-----|-----|
| 到期词 0 个 | 直接学新词 |
| 上限 20 个 | 学 20 个新词 |
| 新词 10 个 | 学完 10 个新词，显示完成 |

**场景 4：无到期词，无新词**

| 条件 | 结果 |
|-----|-----|
| 到期词 0 个 | 无词可学 |
| 新词 0 个 | 直接显示「今日学习完成」 |

### 1.5 单词掌握等级

用户正确完成一个单词后，该单词进入「掌握等级升级」：

| 完成次数 | 等级名称 | 下次复习时间 |
|:-------:|:-------:|:-----------:|
| 第 1 次 | 初学 | 1 天后 |
| 第 2 次 | 熟悉 | 2 天后 |
| 第 3 次 | 认识 | 4 天后 |
| 第 4 次 | 熟练 | 7 天后 |
| 第 5 次 | 精通 | 15 天后 |
| 第 6 次 | 专家 | 30 天后 |
| 第 7 次 | 已掌握 | 永不复习 |

**说明：**
- 输入错误不降级，只需重新输入当前字母
- 正确完成整个单词后自动升级等级，无需用户操作

### 1.6 单词输入流程

```
用户看到当前单词
        ↓
按任意键开始
        ↓
逐个字母输入
        ↓
┌─────────────────────────────────────┐
│  输入正确                            │
│  → 字母变绿色                        │
│  → 继续输入下一个字母                 │
│                                      │
│  输入错误                            │
│  → 字母变红色                        │
│  → 短暂闪烁后清空                    │
│  → 用户重新输入该字母                 │
└─────────────────────────────────────┘
        ↓ 全部字母正确输入完成
自动切换到下一个单词
```

### 1.7 界面需求

| 元素 | 说明 |
|-----|-----|
| 单词显示 | 大字体居中显示当前单词 |
| 输入状态 | 实时显示字母匹配状态（正确绿色/错误红色） |
| 进度指示 | 显示当前进度（如 5/20） |
| 统计信息 | 今日已学/已复习数量 |
| 发音按钮 | 点击播放单词发音 |
| 翻译切换 | 显示/隐藏单词翻译 |

### 1.8 交互行为

| 操作 | 结果 |
|-----|-----|
| 正确输入完成 | 升级掌握等级，自动切换下一词 |
| 输入错误 | 显示错误提示，短暂后清空，重新输入 |
| 点击发音 | 播放单词音频（美音/英音可切换） |
| 切换翻译 | 显示/隐藏单词释义 |
| 达到上限 | 显示完成页面，统计今日数据 |

## 问题分析与修复方案

### 当前代码存在的问题

#### 问题一：单词获取逻辑与需求不符

**当前代码行为：**
- 有到期词 → 只返回到期词，不包含新词
- 无到期词 → 只返回新词
- 每次固定返回最多 20 个

**需求期望：**
- 有到期词 → 先返回到期词，剩余配额给新词
- 例如：上限 20，到期词 5 个 → 返回 5 个到期词 + 15 个新词
- 上限 20，到期词 25 个 → 只返回 20 个到期词

**举例说明差距：**

| 场景 | 当前代码返回 | 需求期望返回 |
|-----|------------|-------------|
| 到期词 5 个，上限 20 | 5 个到期词（无新词） | 5 个到期词 + 15 个新词 |
| 到期词 25 个，上限 20 | 20 个到期词 | 20 个到期词（符合） |
| 到期词 0 个，上限 20 | 20 个新词 | 20 个新词（符合） |

#### 问题二：未考虑"今日已学数量"

**当前代码行为：**
- 每次打开应用，都重新获取 20 个单词
- 不检查"今天已经学了几个"

**需求期望：**
- 打开应用时，检查今日已学数量
- 剩余配额 = 每日上限 - 今日已学数量
- 只获取剩余配额数量的单词

**举例说明差距：**

用户今天已经学了 15 个单词，再次打开应用：

| 当前代码行为 | 需求期望行为 |
|------------|-------------|
| 获取 20 个新单词 | 剩余配额 = 20 - 15 = 5 |
| 用户总共学 35 个 | 只获取 5 个单词 |
| | 学完 5 个后显示"完成" |

#### 问题三：缺少完整流程测试

**当前测试覆盖：**
- 只测试单个函数的单元逻辑
- 例如：测试 `getDueWords` 能正确返回到期词
- 例如：测试 `getNewWords` 能正确返回新词

**缺少的测试：**
- 完整学习流程测试（打开应用 → 学习 → 完成）
- 配额计算场景测试（今日已学 + 剩余配额）
- 多日连续学习测试（跨天数据清理）
- 边界场景测试（无词可学、达到上限等）

---

### 修复方案

#### 方案一：重新设计单词获取逻辑

**新增数据获取函数：**

```
获取今日学习单词（输入：词库ID，单词列表，每日上限）

步骤 1：获取今日已学数量
        今日已学 = 今日新学数量 + 今日复习数量

步骤 2：计算剩余配额
        剩余配额 = 每日上限 - 今日已学数量
        如果剩余配额 ≤ 0，返回空列表

步骤 3：获取到期词
        到期词 = 从词库中筛选到期的单词
        取前 N 个（N = min(剩余配额, 到期词总数)）

步骤 4：如果到期词数量 < 剩余配额
        新词配额 = 剩余配额 - 到期词数量
        新词 = 从词库中筛选未学习的单词
        取前 M 个（M = min(新词配额, 新词总数)）

步骤 5：合并返回
        返回 = 到期词 + 新词
```

#### 方案二：补充端到端测试场景

**场景测试清单：**

| 测试场景 | 描述 |
|---------|-----|
| 首次打开 | 无进度，获取新词 |
| 已学部分 | 今日已学 10 个，上限 20，获取 10 个 |
| 已达上限 | 今日已学 20 个，显示完成 |
| 跨天清理 | 第二天打开，昨日数据清零 |
| 到期词优先 | 有到期词 5 个 + 新词，先返回到期词 |
| 到期词超限 | 到期词 30 个，上限 20，只返回 20 个 |
| 无词可学 | 无到期词 + 无新词，显示完成 |

## 功能模块二：自定义词典

### 2.1 功能概述

支持用户导入 JSON/Excel 格式的自定义词典，实现个性化单词库管理。

### 2.2 支持格式

#### JSON 格式

```json
[
  {
    "name": "apple",
    "trans": ["苹果", "苹果树"],
    "usphone": "ˈæp.l",
    "ukphone": "ˈæp.l"
  },
  {
    "name": "book",
    "trans": ["书", "预订"],
    "usphone": "bʊk"
  }
]
```

**字段说明：**

| 字段 | 必填 | 说明 |
|-----|-----|-----|
| name | ✓ | 单词文本 |
| trans | ✓ | 翻译数组 |
| usphone | | 美式音标 |
| ukphone | | 英式音标 |

#### Excel 格式

| 列名 | 必填 | 说明 |
|-----|-----|-----|
| name | ✓ | 单词文本 |
| trans | ✓ | 翻译（多个用逗号分隔） |
| usphone | | 美式音标 |
| ukphone | | 英式音标 |

### 2.3 词典管理功能

| 功能 | 描述 |
|-----|-----|
| 导入词典 | 选择 JSON/Excel 文件导入 |
| 查看词典列表 | 显示已导入词典及其词量 |
| 删除词典 | 移除已导入的自定义词典 |
| 启用/禁用 | 控制词典是否参与学习 |
| 词典排序 | 设置词典查询优先级 |

### 2.4 数据存储

- **词典元数据**：存储于 uTools DB，包含 ID、名称、词量、启用状态
- **词典数据**：词典内容存储于 uTools DB，以词典 ID 为键

### 2.5 导入流程

```
选择文件 → 解析内容 → 验证格式 → 创建词典 ID → 存储数据 → 更新词典列表
```

### 2.6 界面需求

| 元素 | 说明 |
|-----|-----|
| 导入按钮 | 点击选择文件导入 |
| 词典列表 | 显示已导入词典卡片 |
| 词量显示 | 每个词典显示词条数量 |
| 操作按钮 | 删除、启用/禁用、排序 |
| 导入反馈 | 显示导入进度和结果 |

## 功能模块三：MDX 词典

### 3.1 功能概述

支持导入和查询 MDX 格式词典，获取丰富的词典释义和资源。

### 3.2 MDX 格式说明

MDX 是通用的词典文件格式，支持：
- HTML 富文本释义
- 图片、音频等资源（配套 MDD 文件）
- 词性、例句、搭配等详细信息

### 3.3 词典管理功能

| 功能 | 描述 |
|-----|-----|
| 添加词典 | 选择 MDX 文件添加 |
| 资源加载 | 自动加载同名 MDD 资源文件 |
| 词典排序 | 设置查询优先级顺序 |
| 删除词典 | 移除已添加的 MDX 词典 |
| 查看路径 | 显示词典文件路径 |

### 3.4 查词功能

| 功能 | 描述 |
|-----|-----|
| 输入查词 | 输入单词查询释义 |
| 多词典查询 | 按优先级依次查询所有词典 |
| 结果展示 | HTML 渲染词典释义内容 |
| 资源显示 | 图片、音频等资源正确显示 |

### 3.5 查词入口

1. **主界面查词**：通过 uTools 命令「查词典」触发
2. **文本选词**：选中英文文本后触发查词
3. **学习页查词**：学习中点击单词查看详细释义

### 3.6 查词结果处理

```typescript
// MDX 查询结果处理流程
1. 获取 HTML 释义内容
2. 替换资源引用为 base64 内嵌
   - 图片：<img src="...">
   - 音频：<audio src="...">
3. 提取音标信息（美音/英音）
4. 提取翻译文本（用于学习页显示）
5. 返回结构化结果
```

### 3.7 界面需求

**词典管理页：**

| 元素 | 说明 |
|-----|-----|
| 添加按钮 | 选择 MDX 文件添加 |
| 词典列表 | 显示已添加词典，支持排序 |
| 词典信息 | 名称、路径、排序序号 |
| 操作按钮 | 上移/下移/删除 |

**查词结果页：**

| 元素 | 说明 |
|-----|-----|
| 词典分组 | 每个词典结果独立展示 |
| 折叠展开 | 点击展开/折叠释义内容 |
| 富文本渲染 | HTML 释义正确渲染 |
| 音频播放 | 词典内音频可播放 |

```
┌─────────────────────────────────────────┐
│  DictService (统一查询入口)              │

│  queryWord(word) → 按优先级查询          │
│  queryWordInDicts(word, dictIds) → 指定词典 │
└─────────────────────────────────────────┘
              ↓
┌──────────────────┐  ┌──────────────────┐

              ↓              ↓

```
