# 页面版运行时支持方案

## 背景

当前项目的业务逻辑、页面初始化和词库存储仍然默认依赖 uTools 运行时。结果是：

- 页面版虽然还能启动，但关键配置与本地词库链路并不完整。
- 许多测试只覆盖纯算法，没有覆盖真实页面初始化、当前词库恢复、词库读取与持久化边界。
- 一旦脱离 uTools 宿主，问题难以复现，修复也难以验证。

这次调整的目标不是移除 uTools，而是把它收口为一个平台适配层，让页面版和 uTools 版共享同一套业务与页面逻辑。

## 目标

1. 页面版可以在没有 uTools 宿主的情况下正常打开、读取配置、管理本地词库并进入主要学习页面。
2. 业务逻辑不直接依赖 `window.utools`、`preload.js` 暴露函数或 uTools 专有存储接口。
3. 测试分层清晰：算法测规则，集成测试测真实用例链路，少量页面测试只验证关键交互与恢复。

## 实施计划

### 第一阶段：运行时存储解耦

1. 新增通用存储入口，统一处理：
   - uTools 环境：`window.utools.db`
   - 页面环境：`localStorage`
   - 测试环境：内存或 jsdom `localStorage`
2. 将配置 atom 的持久化从 uTools 专用实现调整为运行时自适应实现。
3. 将本地词库 repository 改为运行时自适应实现，页面层不再直接依赖 uTools 专用 repository。

### 第二阶段：页面链路解耦

1. 将词库加载、初始化和当前词库恢复改为依赖通用 repository。
2. 保留旧的 uTools 路径作为兼容转发，避免一次性改动过大。
3. 页面入口在无 uTools 时仍可完成：
   - 词库列表加载
   - 当前词库恢复
   - 正常学习页加载本地词库

### 第三阶段：测试重整

1. 保留 domain 层纯函数测试，继续验证学习规则。
2. 增加 repository contract test，保证同一套读写语义在 uTools/localStorage 下行为一致。
3. 增加页面初始化相关的 jsdom 集成测试，覆盖：
   - 当前词库恢复
   - 本地词库配置读取
   - 页面环境下的配置持久化
4. 页面 E2E 只保留少量关键流程，不再承担主要逻辑验证职责。

## 本次提交范围

本次先完成第一阶段的第一批落地：

1. 增加通用运行时存储 API。
2. 配置 atom 持久化改为运行时自适应。
3. 本地词库 repository 改为运行时自适应。
4. 页面与 feature 层改用通用 repository 入口。
5. 补充对应测试。

## 验收标准

### 第一批验收

1. 在没有 `window.utools` 的页面环境中，配置项仍可写入并恢复。
2. 在没有 `window.utools` 的页面环境中，本地词库配置与词库内容可正常读写。
3. 生产代码中新增的页面与 feature import 不再继续扩大 `.utools` 专用路径依赖。
4. 新增测试覆盖：
   - 通用存储在 localStorage 下可用
   - 本地词库 repository 在页面环境下可用
5. 相关测试通过。

### 阶段完成标准

1. 页面版能够在浏览器中使用本地持久化完成主要学习流程调试。
2. uTools 版继续复用同一套业务逻辑，仅在平台适配层保留宿主差异。
3. 逻辑测试不再以“纯算法通过”替代“真实链路可运行”。
